Первый тест потокового TTS — инструкция ручной проверки

Запуск из корня проекта:
  npm install
  npm run lint
  node --test tests/tts-test.mjs
  npm run build
  npm run dev -- --port 3100

До запуска задать OPENAI_API_KEY только в серверном окружении или .env.local.
Не коммитить ключ. Основной Realtime endpoint также использует это имя переменной.
Тестовый маршрут: http://localhost:3100/dev/voice-test
localhost в данном отчёте относится к компьютеру, на котором запущен Next.js.

1. Открыть страницу в Chrome/Edge, затем на нужном мобильном браузере.
2. Ввести новый украинский текст; нажать «Озвучити».
3. Убедиться, что звук начинается до окончания получения audio stream.
4. Перебить в середине речи. Звук прекращается, idle не паузится/не перематывается.
5. Сразу запустить другую фразу: старый звук не должен возобновиться.
6. Нажать «20 запусків API»: это 20 последовательных платных запросов с разными
   длинами текста. Кнопка «Перебити» также прекращает серию.
7. Для холодного клиента перезагрузить вкладку. Записать хотя бы один cold-client
   запуск отдельно; остальные обозначаются warm-client. Статус upstream cache
   неизвестен и не выдаётся за cold/warm OpenAI.
8. Сохранить CSV кнопкой. Он содержит только метрики/длину текста/browser UA,
   а не введённый текст, аудио или ключ. Обновление страницы очищает результаты.
9. Сравнить p50/p95 firstRenderedMs, serverFirstByteMs и число underruns.
   Проверить как минимум короткую фразу, несколько предложений и длинный текст.
10. Открыть главную страницу и убедиться, что прежний WebRTC работает как раньше.

Интерпретация метрик:
firstByteMs: от клика до первого сетевого блока PCM в браузере.
serverFirstByteMs: от server dispatch до первого upstream блока; отдельные часы.
scheduledMs: начало рендера AudioWorklet после 150 мс начального буфера.
firstRenderedMs: первый ненулевой sample в AudioWorklet, не акустический замер.
baseLatencyMs/outputLatencyMs: оценки browser/device latency, если поддерживаются.
interruptToClearMs: задержка обработки команды очистки в AudioWorklet.
interruptToLastSampleMs: положительный хвост до последнего ненулевого sample.
underruns: число эпизодов нехватки PCM после начала речи, не число пустых quantum.
При EOS короткое аудио проигрывается даже при недостигнутом начальном буфере.

Результат текущего окружения:
lint PASS; production build PASS; 5 unit/stream tests PASS (mock PCM/upstream).
Нет отдельного typecheck script; проект на JavaScript.
OPENAI_API_KEY отсутствует. Реальных TTS запросов выполнено 0.
Реальные p50/p95, голос, browser playback и desktop/mobile visual check НЕ проверены.
agent-browser здесь не запускается (daemon exited); dev server недоступен
из отдельного процесса проверки. Эти ограничения не являются результатом API.
Не включать mock durations в CSV реальных измерений.

После реальной проверки передать CSV пользователю и остановиться.
GPT streaming, микрофон, VAD и новые cues/lip sync — отдельные следующие задачи.
