# Правила работы Codex

Эти правила обязательны для всех задач Codex в этом репозитории.

## 0. Режим работы: DEFAULT DENY

По умолчанию **запрещено всё, что прямо не разрешено текущей задачей**.

Если в Issue нет явного разрешения на действие, файл, зависимость, сервис или изменение архитектуры — **не делай этого**.

Если для выполнения задачи неожиданно требуется выйти за пределы разрешённого scope:
1. остановись;
2. объясни, что именно мешает;
3. перечисли минимальное дополнительное изменение;
4. дождись явного разрешения пользователя.

Не принимай такое решение самостоятельно.

## Язык общения

- Общайся с пользователем **на русском языке**.
- План изменений, промежуточные сообщения и итоговый отчёт пиши на русском.
- Текст интерфейса приложения меняй только по требованиям конкретной задачи.

## Scope

1. Реализуй **только** явно поставленную задачу.
2. Не расширяй scope.
3. Не реализуй будущие функции.
4. Не переделывай несвязанный интерфейс.
5. Не рефактори несвязанный код.
6. Не меняй архитектуру без явного разрешения.
7. Не делай «заодно», «для удобства», «на будущее», «best practice cleanup» или «улучшение структуры», если этого нет в задаче.

## Разрешённые файлы

Если в Issue есть раздел **«Разрешённые файлы»**, это жёсткий allowlist.

- Можно создавать/изменять **только** перечисленные там файлы.
- Любой другой файл считается запрещённым.
- Если выяснилось, что нужен ещё один файл — остановись и запроси разрешение.
- Не изменяй документацию проекта, если Issue прямо этого не требует.

## Перед началом работы

Перед изменениями:

1. Прочитай:
   - `README.md`
   - `MVP.md`
   - `ARCHITECTURE.md`
   - `CODEX_RULES.md`
   - текущую GitHub Issue.
2. Напиши:
   - какие файлы собираешься создать;
   - какие файлы собираешься изменить;
   - нужны ли новые зависимости;
   - какие команды собираешься запускать, кроме проверок и dev-сервера.
3. **Не начинай изменения, если твой план выходит за allowlist Issue.**
4. Если задача конфликтует с архитектурой или scope — остановись и сообщи об этом.

## Зависимости

- Не добавляй пакеты, если они не нужны для конкретной задачи.
- Не обновляй существующие зависимости без явного указания.
- Не запускай `npm audit fix`, `npm update`, автоматические миграции или массовые обновления.
- Не меняй package manager.
- Не создавай lock-файлы другого package manager.
- Не добавляй UI-kit, state manager, CSS framework, analytics, auth SDK или другие «полезные» библиотеки без прямого указания.

## Запрещённые действия

Без отдельного явного разрешения запрещено:

- удалять существующие файлы;
- переименовывать или перемещать существующие файлы;
- менять `README.md`, `MVP.md`, `ARCHITECTURE.md`, `CODEX_RULES.md`;
- создавать дополнительные страницы, роуты, API routes или backend endpoints;
- создавать БД, миграции, auth, analytics, telemetry;
- добавлять CI/CD, GitHub Actions, Docker, инфраструктурные конфиги;
- создавать или менять `.env*` файлы;
- добавлять реальные API keys, secrets или credentials;
- выполнять сетевые интеграции, не указанные в задаче;
- форматировать весь репозиторий;
- запускать автофиксы по всему проекту;
- менять git history;
- выполнять `git reset --hard`, `git clean`, force push, rebase или squash;
- merge-ить ветки или PR;
- закрывать Issue;
- исправлять несвязанные баги;
- внедрять функциональность «на будущее».

## Изменения

- Трогай только файлы, необходимые для текущей задачи и разрешённые Issue.
- Сохраняй рабочее поведение вне текущей задачи.
- Не делай попутную «чистку».
- Не переименовывай несвязанные компоненты, маршруты и переменные.
- Предпочитай минимальный diff.
- Если можно выполнить задачу 20 строками вместо 200 — выбирай меньший вариант.

## Если заметил другую проблему

Если обнаружил несвязанный баг, улучшение или архитектурный вопрос:

- не исправляй его;
- не создавай для него код;
- просто укажи отдельно в итоговом отчёте.

## Проверка

После завершения задачи выполни только применимые проверки:

- lint;
- typecheck;
- tests, если есть;
- production build.

После этого, если задача создаёт или изменяет пользовательский интерфейс, **запусти приложение для ручной проверки**.

Для локального dev-сервера по умолчанию используй **порт 3100**, если он свободен. Если 3100 занят — выбери другой свободный порт и явно сообщи его.

В финальном сообщении обязательно дай адрес проверки, например:

`http://localhost:3100`

Не останавливай dev-сервер до окончания текущей рабочей сессии, если среда позволяет оставить его запущенным.

## Git workflow

- Одна задача = один маленький проверяемый commit максимум.
- Не создавай дополнительные commits «для cleanup».
- Не объединяй несколько функций или несвязанных исправлений.
- Не merge-ь ничего самостоятельно.
- Не закрывай Issue самостоятельно.
- Не создавай PR, если это отдельно не попросили.
- Не делай force push и не переписывай историю.

## Итоговый отчёт

В конце каждой задачи напиши:

1. какие файлы созданы;
2. какие файлы изменены;
3. что именно изменено;
4. какие зависимости добавлены, если были;
5. результаты lint/typecheck/tests/build;
6. адрес запущенного приложения для ручного теста, если применимо;
7. несвязанные проблемы, которые заметил, но не исправлял.

После этого **остановись**.

Не переходи к следующей логичной функции без явного разрешения.
